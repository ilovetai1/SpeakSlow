# SpeakSlow 2.1.0 開發規劃

本次先提交既有內容，再進入 **2.1.0 開發版**。新功能只有規劃，尚未實作、打包、安裝或發佈。

| 範圍 | 使用者看得到的功能 | 預設與界線 |
|---|---|---|
| 3：情境潤稿 | 中性／訊息／郵件／筆記模式，可設定 App 預設；可讓本機 AI 參考有限的選取與前後文 | 中性預設保留原行為；外部文字情境預設關閉，第一版只供 Ollama 使用 |
| 4：改錯學習 | 在本次輸入後觀察小幅改詞，加入「待學習」；核准、忽略或撤回 | 被動追蹤預設關閉；核准前不套用；預設限當次 App；不送雲端 |
| 6：延遲量測 | 看錄音準備、辨識、潤稿、情境讀取、貼上命令的 P50／P95、樣本及失敗數 | 本機無文字資料；可關閉、清除、匯出；不足 30 筆不作速度比較 |

App 詞庫以本次辨識後套用字典時取得的 App 情境為準，画面顯示採用的詞庫。辨識／潤稿中切到另一個 App 不會鎖定或還原貼上目的地；仍沿用既有 current-cursor 輸出，下一次辨識再取新的詞庫情境。

## 交付順序

1. **延遲基線**：先完成本機計時與統計，驗證資料白名單、時鐘與缺測，再量測目前流程。
2. **情境潤稿**：建立唯讀 macOS reader、寫作 profile 與本機 context；使用合成語料及可控文字欄位驗收。
3. **改錯學習**：共用 reader，先確認本次插入範圍，再產生候選及 App 範圍規則；驗證核准／忽略／撤回。
4. **2.1.0 整合驗收**：做功能開關 off/on 回歸、至少 32 組語料及 30 組有效實機 paired trials，记录結果與不支援 App。

各階段通過自身驗收才進下一階段。helper protocol 的 mock 通過不代表 App 真正支援；模型 request 成功不代表語意正確。未量測的性能結果標為未量測。

## 保留的行為

- 本機 ASR／Ollama 與現有 provider 設定、潤稿 prompt、500 字上限、model 選擇與 timeout。
- 原有貼上／Enter、single-flight／取消、歷史／音檔救援與留存流程；前次評估 1、2、5 不在本次新功能範圍。
- 既有面板手動點字改錯仍按原契約記入全域字典；新被動學習另有開關與待核准流程。
- 遠端 provider 可使用不含外部文字的 profile；不會因新功能取得周邊文稿。

- `proposal.md`：範圍與能力清單。

# 錄音指示器在移除外接螢幕後消失

日期：2026-10-28。本機修正版：2.1.0；未發佈遠端版本。

## 現象與證據

使用者確認，問題發生情境包含：雙螢幕時啟動 SpeakSlow，使用途中移除外接螢幕，改用筆電螢幕錄音。語音仍能正常轉成文字，但錄音指示器有時不顯示。

修正前的實機觀察：指示器原生視窗存在，錄音狀態仍有效，也沒有隱藏事件，但它不在 macOS 的 `optionOnScreenOnly` 視窗清單。另一次測試中，主面板顯示時指示器可見，主面板關閉後不可見。單獨的 Dock／全螢幕對照未能穩定重現，因此不能把 Dock 轉換視為唯一根因。

已確認的程式缺口：指示器會更新座標，但一直重用同一個原生 panel；未處理顯示器新增／移除，也沒有驗證 `showInactive()` 後是否實際出現在目前桌面。底層 macOS 如何形成失效視窗狀態仍未完全定位。

## 修正

- 顯示器新增或移除時，清除舊指示器。若仍在錄音，重建原生 panel 並依目前游標所在的有效螢幕定位；未錄音時等待下次開始才建立。
- 等待尚未完成的載入後再處理配置變更。停止錄音、關閉或較新的配置變更可以取消舊操作。
- macOS 錄音期間每 1.2 秒查核一次原生可見性。連續兩次不可見才恢復，以容許短暫桌面切換。最多兩次：先重新設定 Space 旗標並顯示，再重建視窗。仍失敗則回報錯誤，不無限重試。
- 恢復使用 `skipTransformProcessType` 與 `showInactive()`，保留 Dock 行為與輸入焦點。停止錄音時取消檢查，晚到的結果不會重新顯示視窗。
- 新增的 Swift helper 只回傳指定、由呼叫者擁有的視窗是否可見，不擷取畫面、視窗名稱或其他 App 內容。隨 macOS App 打包。
- 日誌改為「已要求顯示錄音指示器」，不把呼叫 API 當成 macOS 顯示成功的證據。
- 螢幕事件在建立指示器時才註冊，避免在 `app.ready` 之前存取 Electron `screen`。

Electron 31.7.7 的 [panel 原始碼](https://github.com/electron/electron/blob/v31.7.7/shell/browser/ui/cocoa/electron_ns_panel.mm)本身已加入跨桌面旗標，因此本次不以單純新增相同旗標作為完整修復。

## 驗證結果

- 螢幕移除的三項回歸測試先失敗，修正後通過：錄音中移除、未錄音時移除、載入中移除後立即停止。
- 全套 Node 回歸：167 項，164 通過、3 跳過、0 失敗。補強啟動順序後的相關測試：14 項全通過。
- 原生故障注入：直接讓 BrowserWindow 隱藏但保留管理器的錄音狀態。舊程式等待後仍不可見；修正後恢復為可見。這是失效狀態的注入測試，不宣稱等同實際拔線的底層原因。
- 第一階段恢復無效的注入測試：舊視窗無法重新顯示，第二階段重建為新的原生視窗後可見。前景 App 保持外部 App，停止後指示器保持隱藏。
- renderer 與 arm64 App 建置通過。首次安裝驗證抓到提前存取 `screen` 的啟動錯誤；修正註冊時機並重新安裝後，實際啟動通過。
- 安裝版實際錄音觀察：`onScreen=true`；停止後 `onScreen=false`，沒有指示器查核錯誤。
- **使用者實測確認：SpeakSlow 已啟動時拔掉外接螢幕，改用筆電螢幕錄音，動態視窗正常出現。**
- 使用 `npm run install:mac -- --source /Users/chunghan/AI/SpeakSlow/dist/indicator-fix-20261028/mac-arm64/SpeakSlow.app --identity -` 安裝。簽章驗證、安裝版程式與工作目錄內容比對通過；專案完整 `.app` 副本為零，`/Applications` 與 Spotlight 僅找到 `/Applications/SpeakSlow.app`。保留既有 DMG／ZIP。

本機驗證紀錄位於 `dist/indicator-fix-20261028/validation/`，包含回歸輸出、原生故障注入前後結果、安裝報告與測試原始碼。未把這次結果延伸為所有 macOS 版本、螢幕配置或長時間使用情境的驗證。
